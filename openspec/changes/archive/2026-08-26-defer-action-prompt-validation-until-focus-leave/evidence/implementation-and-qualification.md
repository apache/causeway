# Implementation and qualification

## Implementation

The standard interaction controller now tracks prompt-local parameter ids whose prepared validation may be presented.
Initial preparation still resolves all GraphQL-authoritative structure and capabilities, but untouched validity and parameter errors are omitted from markup and accessibility relationships.
Input and change events retain codec-produced pending values locally and no longer schedule debounced parameter preparation.
Autocomplete input retains its independent debounced suggestion path.

Native editor `focusout` commits the field directly.
Qualified field and reference adapters publish an internal value-free completion signal containing only parameter and next-control names because Vaadin focus events do not cross the adapter boundary reliably.
The controller ignores completion generated by its own rerender, commits through `setParameterValue`, and restores the browser-selected next prompt control after replacement.
Disconnected or stale adapter controls cannot publish obsolete completion work.

Invoke marks every parameter validation-visible, refreshes authoritative parameter state using the complete latest pending values, then runs whole-action validation before invocation.
The first edit after a displayed error clears that presentation and re-enables correction without requesting preparation while typing.
Protected values remain filtered from markup and semantic prompt events.
