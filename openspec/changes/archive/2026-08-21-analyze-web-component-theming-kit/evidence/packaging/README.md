# Maven packaging demonstration

This analysis-only Maven project proves that pinned candidate assets can be placed in a conventional JAR under `META-INF/resources` with their license files.
It is not part of the repository reactor and must not become a production dependency.

## Build

First recreate the pinned npm assets:

```shell
cd ../harness
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci --ignore-scripts --no-audit --no-fund
npm run build-webawesome
cd ../packaging
mvn package
```

The output JAR is `target/causeway-theming-candidate-assets-1.0.0-analysis.jar`.
Inspect it with:

```shell
jar tf target/causeway-theming-candidate-assets-1.0.0-analysis.jar
```

The expected roots are:

- `META-INF/resources/causeway-toolkit/bootstrap`
- `META-INF/resources/causeway-toolkit/webawesome`
- `META-INF/resources/causeway-toolkit/open-props`
- `META-INF/licenses/bootstrap`
- `META-INF/licenses/webawesome`
- `META-INF/licenses/open-props`

## Candidate-specific production paths

### Bootstrap

Bootstrap 5.3.8 is already available to the wider repository through Maven WebJar coordinates.
A production implementation can declare an explicit WebJar dependency and serve the compiled CSS without introducing npm.
Bootstrap JavaScript and Popper are excluded from the CSS-only prototype and would require separate dependency and behavior review.

### Web Awesome

No current Web Awesome WebJar was found in Maven Central during the evaluation.
A production implementation would run pinned `npm ci` from Maven, selectively bundle required components, and package generated immutable assets and licenses into the foundation JAR.
The analysis JAR packages the reproducible selective JavaScript and CSS bundles generated by `npm run build-webawesome` rather than the 662-file browser distribution.

### Open Props

Maven Central contains `org.webjars.npm:open-props`, but the indexed WebJar version trails the frozen npm release.
A production implementation can either update the WebJar or run pinned npm acquisition and copy only the selected CSS prop packs into the foundation JAR.
No Open Props JavaScript runtime is required.

## Release boundary

A production proposal must make Maven the single release entry point, verify `package-lock.json`, disable package lifecycle scripts unless reviewed, retain license and notice material, and fail when generated assets differ from their pinned checksums.
The frontend acquisition or bundling step must be isolated from downstream applications, which continue consuming ordinary Maven artifacts.
