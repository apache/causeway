## 1. Pin Inputs and Authoring Use Cases

- [ ] 1.1 Inventory the public component catalogue, object-context contract, generic viewer router registrations, grid fallback, and representative custom-page needs.
- [ ] 1.2 Define equivalence classes for simple forms, action-heavy pages, collections, nested objects, ordinary HTML, application elements, and responsive layouts.
- [ ] 1.3 Define security, accessibility, source-control, round-trip, migration, and build constraints.

## 2. Evaluate Tooling and Authoring Models

- [ ] 2.1 Evaluate GrapesJS against current web-component, plugin, serialization, accessibility, licensing, and maintenance requirements.
- [ ] 2.2 Evaluate a purpose-built semantic tree and at least one other viable web-component authoring approach.
- [ ] 2.3 Compare direct HTML, semantic intermediate model, and constrained hybrid approaches using a scored decision matrix.
- [ ] 2.4 Record rejected approaches and conditions that could justify reconsideration.

## 3. Build Disposable Prototypes

- [ ] 3.1 Prototype palette population from the Custom Elements Manifest and targeted logical-type introspection.
- [ ] 3.2 Prototype member binding, layout containers, nested context constraints, property inspection, collection columns, actions, and ordinary HTML.
- [ ] 3.3 Prototype deterministic export and reopen behavior for portable custom-element HTML and any semantic model.
- [ ] 3.4 Prototype fixture preview and explicitly enabled authenticated live preview with bounded redacted diagnostics.
- [ ] 3.5 Prototype registration with the generic HTMX, Vue, and Svelte router contracts.

## 4. Security, Accessibility, and Compatibility Evidence

- [ ] 4.1 Verify hidden values, passwords, credentials, authorization rules, and resource content never enter models, history, storage, exports, or diagnostics.
- [ ] 4.2 Verify authoring keyboard operation, focus, announcements, structural labels, and generated-page accessibility.
- [ ] 4.3 Measure bundle size, serialization stability, large-page behavior, dependency health, and replacement cost.
- [ ] 4.4 Verify generated pages remain usable without the designer runtime.

## 5. Produce the Roadmap

- [ ] 5.1 Select or reject the production authoring foundation and record the decision rationale.
- [ ] 5.2 Define the versioned page artifact, router registration, extension, migration, and compatibility contracts.
- [ ] 5.3 Split production work into bounded proposals or explicitly defer it if evidence is insufficient.
- [ ] 5.4 Publish the evaluation matrix, prototype evidence, generated examples, security review, and narrative roadmap.
- [ ] 5.5 Run documentation, links, prototype tests, formatting, and strict OpenSpec validation checks.
