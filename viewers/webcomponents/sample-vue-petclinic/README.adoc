This module is the executable reference application for the generic Vue web-component viewer.
It uses the shared deterministic Petclinic domain, the Causeway GraphQL endpoint, Vue 3, Vue Router 4, and the framework-neutral `cw-` elements.
The Vue application owns its HTML document, stable shell, router, history fallback, theme, and exact logical-type page registration.
Its application-owned presentation follows the HTMX Petclinic shell and page compositions documented in link:PRESENTATION-PARITY.adoc[`PRESENTATION-PARITY.adoc`].
The semantic web components remain authoritative for metadata, values, validation, interactions, collections, previews, and results.

== Run

Use JDK 21 and run this command from the repository root:

[source,bash]
----
./viewers/webcomponents/sample-vue-petclinic/run.sh
----

Open these URLs after Spring Boot starts:

* `http://localhost:8080/vue/` uses the default Vaadin component policy.
* `http://localhost:8080/vue/?toolkit=native` uses the native component policy.
* `http://localhost:8080/vue/object/petclinic.PetOwner/s_owner-mary` opens Mary Smith through the exact-type Vue owner page.
* `http://localhost:8080/vue/object/petclinic.Pet/s_pet-basil` opens Basil through the exact-type Vue pet page.
* `http://localhost:8080/vue/object/petclinic.Visit/s_visit-basil-checkup` opens Basil's visit through the exact-type Vue visit page.
* `http://localhost:8080/vue/object/petclinic.ViewerFallback/s_viewer-fallback` demonstrates the generic `<cw-object>` fallback page.
* `http://localhost:8080/graphiql` opens GraphiQL.

Pass Maven properties to the script when needed.
For example, this uses port 9090:

[source,bash]
----
./viewers/webcomponents/sample-vue-petclinic/run.sh \
    -Dspring-boot.run.arguments=--server.port=9090
----

The script respects an existing `JAVA_HOME`, discovers JDK 21 through macOS `/usr/libexec/java_home` when `JAVA_HOME` is unset, and uses `MVN` instead of `mvn` when that environment variable is supplied.

=== Secured variant

Run the local SecMan and Spring Security variant with:

[source,bash]
----
./viewers/webcomponents/sample-vue-petclinic/run-secured.sh
----

Open any `/vue` route and sign in with username `sven` and password `pass`.
The secured launcher preserves the environment and additional Maven argument behavior of `run.sh` while selecting `PetClinicVueSecuredApplication`.
The application restores only safe Vue GET deep links, fetches bounded no-store username and CSRF context before mounting, decorates every GraphQL POST with the current CSRF header, and retains an application-owned non-visual POST logout form.
Invalid, absent, locked, and passwordless accounts have the same public failure, and successful authentication migrates the session identifier.
The authorized tertiary Account menu presents exact framework action `causeway.security.LogoutMenu#logout` as **Sign out**; host policy claims activation and submits the native form before GraphQL, while similarly named application actions and typed local-resource results remain independent.
The secured shell adds no separate visible username or logout block.

== Test

The test script runs the ordinary and secured Spring integration tests and both Playwright acceptance suites.
Playwright uses headless Chromium by default and does not take foreground focus.

Run the suite with:

[source,bash]
----
./viewers/webcomponents/sample-vue-petclinic/test.sh
----

Install Playwright Chromium on the first run when necessary:

[source,bash]
----
./viewers/webcomponents/sample-vue-petclinic/test.sh --install-browser
----

The ordinary browser suite covers the HTMX presentation baseline, wide and narrow layout invariants, the four exact-type pages, stable application shell, direct links, refresh, back and forward navigation, generic fallback, invalid and absent objects, semantic navigation and results, menus, keyboard skip navigation, and both toolkit policies.
The secured browser journey additionally covers generic invalid login, valid deep-link restoration, CSRF-bearing reads and mutation, missing-CSRF rejection, exact host Logout policy, native logout, browser history, and session expiry.
Set `-Dplaywright.headless=false` only when deliberately debugging in a visible browser.
Set `-Dplaywright.chromium.executable=/absolute/path/to/chromium` or `-Dplaywright.chromium.channel=chrome` to use an installed browser.
Any arguments after `--install-browser` are passed to the Maven test invocation.

== Rebuild the Vue frontend

Production Vue assets are committed under `src/main/resources/static/vue` so running the application does not require a Vite development server.
After changing files under `frontend`, regenerate the locked production output from the repository root:

[source,bash]
----
mvn -pl viewers/webcomponents/sample-vue-petclinic \
    -am \
    -Pregenerate-vue-petclinic \
    package
----

The profile runs `npm ci` and the production Vite build.
The frontend config treats `cw-` names as native custom elements and deduplicates Vue and Vue Router while consuming the local viewer package.

== Application structure

`frontend/index.html` is the application-owned HTML document.
`frontend/src/App.vue` declares the stable GraphQL provider, menus, loading and announcement regions, default result outlet, keyed router view, and conditional non-visual native logout form.
`frontend/src/authentication.ts` performs no work for the ordinary document and, for the secured document only, fetches current bounded session context and supplies the CSRF-decorating executor.
The files under `frontend/src/pages` provide exact-type application compositions for `petclinic.HomePage`, `petclinic.PetOwner`, `petclinic.Pet`, and `petclinic.Visit`.
The menu layout is shared with HTMX through the framework-neutral Petclinic domain resources.
The deliberately unregistered `petclinic.ViewerFallback` fixture demonstrates the generic route-page fallback without making a user-visible Petclinic route inconsistent.
`PetClinicVueRouteController` forwards only the intended ordinary client routes to the production `index.html` without capturing GraphQL or static assets.
The secured source set adds `PetClinicVueSecuredRouteController`, which serves the same committed document with only its authentication-context endpoint slot bound; it never embeds a username or token into static assets.

The generic Vue viewer package and its application integration contract are documented in `../vue/README.adoc`.
