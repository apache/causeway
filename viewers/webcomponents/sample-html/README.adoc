The `sample-html` module is a runnable Causeway Spring Boot application and illustrative reference showcase for framework-neutral read-only and interaction web components against a real rich GraphQL endpoint.
Its frontend uses a page-specific responsive application theme built with vanilla HTML, native custom elements, ECMAScript modules, and plain CSS.
It has no npm build, HTMX, Playwright, or frontend-framework dependency.

== Application architecture

The application uses the Causeway GraphQL viewer, Causeway JPA persistence with EclipseLink, an in-memory H2 database, security bypass for local verification, and the packaged web-component foundation artifact.
The sample HTML, foundation modules, and `/graphql` endpoint are served from the same origin.

The module is an executable integration fixture and is skipped during Maven install and deployment.

== Build and run

JDK 17 or later is required.
The preferred development launch uses the reactor's `run-sample-html` Maven profile:

[source,shell]
----
export JAVA_HOME="$HOME/.sdkman/candidates/java/17.0.18-tem"
export PATH="$JAVA_HOME/bin:$PATH"

mvn -f viewers/webcomponents/pom.xml -Prun-sample-html
----

The profile selects `spring-boot:run` as its default goal, builds the foundation and sample in reactor order, skips the non-application reactor modules for the run goal, and starts only `sample-html`.
Running from the reactor ensures that the foundation resources, Causeway GraphQL viewer, JPA persistence, H2 database, and security-bypass runtime are all present on the application classpath.
Stop the application with `Ctrl+C`.

To use a different port, pass the Spring Boot application argument through the Maven plugin:

[source,shell]
----
mvn -f viewers/webcomponents/pom.xml -Prun-sample-html \
    -Dspring-boot.run.arguments=--server.port=19186
----

Open the corresponding page:

[source,text]
----
http://localhost:8080/sample-html/index.html
----

For the port-override example, open `http://localhost:19186/sample-html/index.html` instead.
The page imports the foundation entry module from `/causeway-webcomponents/index.mjs` and sends GraphQL operations to the same-origin `/graphql` endpoint.
Wait for `[data-testid="sample-app"]` to reach `data-state="ready"`; `terminal-error` indicates that the required GraphQL schema or object query did not become available.

=== Packaged-jar alternative

To verify the packaged artifact rather than run from compiled classes, build the complete reactor first:

[source,shell]
----
mvn -f viewers/webcomponents/pom.xml -pl sample-html -am package

JAR=$(find viewers/webcomponents/sample-html/target \
    -name 'causeway-viewer-webcomponents-sample-html-*.jar' \
    ! -name '*-sources.jar' \
    ! -name '*-javadoc.jar' \
    ! -name '*.original' | head -1)
java -jar "$JAR"
----

== Deterministic sample data

The application creates one root JPA entity and two related JPA entities during startup.
The root identity and expected values are:

[cols="1,2"]
|===
|Contract |Value

|Logical type
|`causeway.webcomponents.sample.SampleObject`

|Persisted string identifier
|`sample-1`

|Causeway bookmark and component `object-id`
|`s_sample-1`

|Title
|`Framework-neutral components [WC-001]`

|Visible scalar property
|`name = Framework-neutral components`

|Disabled scalar property
|`code = WC-001`, disabled because `The sample code is fixed.`

|Hidden property
|`secret` is present but its value is intentionally not reproduced by the page or this guide

|Representative text
|`summary = A deterministic reference page composed entirely from semantic Causeway web components.`

|Representative number
|`capacity = 24`

|Representative boolean
|`featured = true`

|Enum property
|`status = ACTIVE`

|Null property
|`notes = null`

|Object-valued property
|`relatedObject = causeway.webcomponents.sample.SampleRelatedObject:s_related-1`

|Enabled action state
|`inspect`, visible with no disabled reason

|Disabled action state
|`archive`, disabled because `Archiving is disabled in the read-only sample.`

|Hidden action state
|`hiddenAction`, present in the rich schema with `hidden = true`

|Property validation
|`summary` requires at least 12 characters and `capacity` must be between `1` and `100`

|Safe scalar action
|`inspect`, invoked through the rich query and returns the object title

|Parameterized mutating action
|`updateDetails(summary, status)`, with defaults, enum choices, validation, object result, and top-level mutation placement

|Safe collection action
|`findRelated(search)`, with autocomplete and a related-object collection result

|Void mutating action
|`clearNotes`, invoked through a top-level mutation and followed by context refresh
|===

The populated `relatedObjects` collection contains these deterministic rows:

[cols="1,1,2,1"]
|===
|Bookmark |Logical type |Name |Code

|`s_related-1`
|`causeway.webcomponents.sample.SampleRelatedObject`
|`Schema-driven components`
|`ROW-001`

|`s_related-2`
|`causeway.webcomponents.sample.SampleRelatedObject`
|`Framework-neutral composition`
|`ROW-002`
|===

The `emptyRelatedObjects` collection returns no rows.
The `s_` prefix is Causeway's string-identifier encoding used by bookmarks and rich GraphQL object lookups.
The `_meta.version` values are supplied through the JPA `HasVersion` contract.

== Expected page and interaction states

The reference page groups semantic content into labelled object-summary, property, action, collection, and live-diagnostic cards.
The object header displays `Framework-neutral components [WC-001]` and the root bookmark.
The `name`, `summary`, `capacity`, `featured`, `status`, null `notes`, and related-object link render through the standard value registry.
Ordinary values are enabled at the Causeway metamodel level, while the `code` property, related-object property, and `archive` action display deliberate disabled reasons.
The `secret` property and `hiddenAction` render no semantic content, and the coverage guide explains their absence without reproducing a hidden value.
The `summary`, `capacity`, `featured`, `status`, and `notes` properties expose explicit edit affordances, while the page remains read-only for every property without `editable`.
The standard interaction controller invokes `inspect` directly, opens an accessible prompt for `updateDetails` and `findRelated`, executes `clearNotes`, and publishes typed semantic results without automatic navigation.

Both collections are activated declaratively by the sample page.
`relatedObjects` loads through a secondary context-owned operation and renders the declared `name` and `code` columns.
Its returned metadata and wrapper data hydrate row contexts without repeating the selected object reads.
The diagnostics card reports `2 rows loaded` through `collection-related-count`.
`emptyRelatedObjects` renders the accessible `No items` status.
The page-specific cards, typography, focus treatment, and collection framing adapt to narrow and wide viewports and light and dark color schemes.

`[data-testid="sample-app"]` exposes the latest semantic object-context status through its `data-state` attribute.
Automation should wait for `data-state="ready"` or fail with the diagnostic state when it becomes `partial-error` or `terminal-error`.
The application also updates `aria-busy` during `schema-loading` and `object-loading`.

A future Playwright test can therefore begin with a wait equivalent to:

[source,javascript]
----
await page.goto('/sample-html/index.html');
await page.locator('[data-testid="sample-app"][data-state="ready"]').waitFor();
----

Each editable property derives additive hooks from its existing host selector: for example, `property-summary-edit`, `property-summary-editor`, `property-summary-save`, and `property-summary-cancel`.
Playwright itself is intentionally not introduced by this slice.

== Manual event verification

Select the object link rendered inside `property-related-object`.
The page prevents no routing, but the plain application listener reports `navigate:causeway.webcomponents.sample.SampleRelatedObject:s_related-1` through `sample-event`.

Select the enabled `inspect` action.
The affordance first reports `action:inspect` through `sample-event`; the standard controller then invokes it and reports `result:inspect:scalar` through `sample-interaction-event`.
Select `updateDetails` to open the standard prompt, observe its prompt states, and invoke a top-level mutation that reports `result:updateDetails:object`.
The disabled `archive` action and hidden `hiddenAction` must not open a prompt or change the result diagnostic.
After the populated collection loads, `collection-related-count` reports `2 rows loaded`.

== Manual browser checklist

. Start the sample with `mvn -f viewers/webcomponents/pom.xml -Prun-sample-html` and wait for `Started SampleHtmlApplication`.
. Probe `/graphql` directly as shown below, open `/sample-html/index.html`, and wait for `sample-app[data-state="ready"]`.
. Confirm the five labelled cards, interaction controls, static coverage guide, existing read-only values, deliberate disabled reasons, hidden states, two collection rows, row count, and empty collection.
. Select `Edit Summary`, cancel, and confirm that no mutation ran and the original value remains.
. Enter a summary shorter than 12 characters, confirm the accessible validation reason and blocked Save control, then enter a valid value, save it, and confirm the refreshed semantic value.
. Edit Capacity with `0` and confirm its range validation; cancel or restore `24`.
. Edit Status, confirm `ACTIVE` and `PAUSED` choices, save a temporary choice, and restore `ACTIVE`.
. Select `Inspect` and confirm a safe query, scalar result, semantic diagnostics, and no prompt.
. Select `Update Details`, confirm defaults and enum choices, submit an invalid short summary, cancel once with Escape, then invoke valid values and confirm the object result and refreshed summary and status.
. Select `Find Related`, type a search that exercises advertised autocomplete, invoke it, and confirm the collection result without navigation.
. Select `Clear Notes` and confirm a void result and context refresh; confirm Archive remains disabled and the hidden action remains absent.
. Repeat edit, cancel, prompt, and invoke flows with keyboard-only Tab, Enter, Space, and Escape operation and confirm focus returns to the originating control.
. Repeat at narrow and wide viewports in light and dark color schemes.
. Confirm property updates and mutating actions use top-level GraphQL mutations, safe actions use rich queries, every `/graphql` request succeeds, the browser console contains no errors, and the accessibility audit reports no failures.

== Automated integration verification

Run the foundation and sample tests from the repository root:

[source,shell]
----
mvn -f viewers/webcomponents/pom.xml -pl sample-html -am test
----

The sample integration test starts the application on a random port and verifies:

* `/sample-html/index.html` is delivered with all documented selectors.
* `/causeway-webcomponents/index.mjs` is delivered from the foundation dependency.
* Independent targeted `__type` operations resolve the root, enum-property, and collection wrapper types without triggering GraphQL Java's bad-faith introspection rejection.
* A real rich GraphQL object lookup resolves `s_sample-1`.
* Object metadata, enabled ordinary properties, text, numeric, boolean, enum, null, reference, enabled-action, disabled-action, hidden-action, and hidden-property state have deterministic values.
* Property validation, enum choices, top-level property mutation, safe query invocation, action defaults, autocomplete, action validation, mutating object result, safe collection result, void mutation, and authoritative restoration use the real endpoint.
* The section, property, editor, action, prompt, result, coverage, event, and collection-count hooks are present while the hidden value is absent from the page source.
* A real secondary-shaped collection operation returns deterministic row metadata and selected `name` and `code` wrappers.
* The empty collection returns zero rows.

The foundation's dependency-free Node tests verify renderer and editor selection, component lifecycle, semantic commands, property state transitions, action prompts and results, accessibility markup, semantic events, lazy collection state, partial errors, cancellation, mutation serialization, stale-response rejection, row hydration reuse, and delta reads without requiring a browser process.

== GraphQL readiness probe and troubleshooting

While the Maven run profile remains active, verify the same-origin endpoint directly:

[source,shell]
----
curl -i \
  -H 'Content-Type: application/json' \
  --data '{"query":"query CausewayProbe { __typename }"}' \
  http://localhost:8080/graphql
----

A healthy response is HTTP `200` with `{"data":{"__typename":"SimpleAndRich"}}`.
If the page reaches `terminal-error`, first confirm the Maven output contains `Started SampleHtmlApplication`, check that port `8080` is not owned by an older process, run the probe, and hard-refresh with the browser cache disabled.
Inspect `document.querySelector('[data-testid="sample-object"]').context.state.error` for the concrete schema or object failure.
For interaction failures, inspect `sample-interaction-event`, the failing `/graphql` response, and the prompt or property alert before retrying.
