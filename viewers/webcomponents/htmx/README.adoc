The `causeway-viewer-webcomponents-htmx` module provides an optional server-routed application shell over the framework-neutral Causeway custom elements.
HTMX owns canonical navigation, fragment replacement, browser history, loading, announcements, and route errors.
The semantic components continue to own GraphQL projections, effective layouts, menus, interactions, validation, mutations, and typed results.

== Enablement

Add `org.apache.causeway.viewer:causeway-viewer-webcomponents-htmx` and import `CausewayModuleViewerWebcomponentsHtmx` in the application bootstrap.
Merely using the foundation component module does not install any HTMX route or asset.
Applications requiring optional local SecMan-backed browser authentication can instead follow link:../htmx-security-secman/README.adoc[`htmx-security-secman/README.adoc`].

The viewer packages `org.webjars.npm:htmx.org:2.0.6` and serves the module-owned browser bridge and shell stylesheet from `/causeway-htmx/`.
The shell uses external same-origin scripts and styles and requires no inline script.

== Configuration

`causeway.viewer.webcomponents.htmx.base-path` defaults to `/htmx` and accepts a bounded non-root origin-relative mount path.
`causeway.viewer.webcomponents.htmx.graph-ql-endpoint` defaults to `/graphql`.
`causeway.viewer.webcomponents.htmx.brand` defaults to `Apache Causeway`.
`causeway.viewer.webcomponents.htmx.language` defaults to `en`.
`causeway.viewer.webcomponents.htmx.application-stylesheet` optionally adds one same-origin application stylesheet after the default theme.
`causeway.viewer.webcomponents.htmx.wicket-comparison-path` optionally adds a footer link and is intended only for comparison samples.
`causeway.viewer.webcomponents.htmx.component-toolkit` accepts `vaadin` or `native` and defaults to `vaadin`.
The Vaadin policy enables qualified reference editors, basic, numeric, and local-temporal editors and read-only fields, ordinary action buttons, and deterministic wide collection Grid presentation, while the native policy is the immediate complete rollback.
`causeway.viewer.webcomponents.htmx.editor-toolkit`, `causeway.viewer.webcomponents.htmx.vaadin-reference-widgets`, and `causeway.viewer.webcomponents.htmx.vaadin-field-families` remain readable for a bounded deprecation period.
An explicit component property wins over every deprecated property.
When the component property is absent, an explicit deprecated editor property maps to the complete component policy so its former native rollback remains complete.
When both common properties are absent but either older pilot property is explicit, the complete former editor-only policy is preserved: references default false and field families default empty unless their corresponding old value is supplied, while read-only fields, action buttons, and Grid remain native.
Unknown, blank, or repeated deprecated family entries fail bounded configuration rather than broadening policy.
`causeway.viewer.webcomponents.htmx.reference-minimum-search-length` defaults to `2`.
`causeway.viewer.webcomponents.htmx.reference-maximum-results` defaults to `50` and is the requested page-size fallback for advertised GraphQL autocomplete windows as well as the accepted complete-response bound for legacy non-windowed autocomplete.
An advertised field's smaller introspected default window size takes precedence.

[source,properties]
----
# Supported default
causeway.viewer.webcomponents.htmx.component-toolkit=vaadin

# Immediate complete rollback and diagnostic comparison
causeway.viewer.webcomponents.htmx.component-toolkit=native
----

The complete shell applies a restrictive same-origin content-security policy and returns `private, no-store`.
The default Vaadin policy adds the deterministic deduplicated union of only the reviewed byte-exact `style-src` and `style-src-elem` SHA-256 sources, retains `style-src-attr 'none'`, and never adds `unsafe-inline`.
The reference, basic, numeric, local-temporal, action-button, and Grid JavaScript closures remain independently route-lazy and are requested only when an eligible connected editor, read-only field, ordinary action, or active wide qualified collection selects them.
Landing, custom, menu-only, narrow-collection, inactive-collection, unqualified-collection, and otherwise unaffected routes therefore make zero Vaadin asset requests even though their policy permits reviewed hashes.
The native policy removes every Vaadin hash and asset request without changing routes, GraphQL, persisted data, or application markup.
Applications adding other third-party resources must deliberately supply an equivalent deployment policy rather than weakening this module silently.

== Toolkit release obligations

The default toolkit is supported only through the checked-in selective reference, field-family, action-button, and Grid closures.
A dependency update must regenerate and review npm integrity, package entry points, production licenses, telemetry opt-out, raw and gzip budgets, SHA-256 checksums, exact style hashes, and same-origin assets as one change.
Reproduce each closure from its `foundation/vaadin-reference`, `foundation/vaadin-fields`, `foundation/vaadin-actions`, or `foundation/vaadin-grid` directory with `npm ci --ignore-scripts`, `npm run build`, `npm run verify`, and `npm run audit`.
Accepted gzip ceilings are 66560 bytes for references, 81920 bytes for basic fields, 66560 bytes for numeric fields, 102400 bytes for local-temporal fields, 204800 bytes for all field families, 65536 bytes for actions, 196608 bytes for Grid, and 533504 bytes for the complete closure set.
Release qualification runs deterministic build verification, zero-vulnerability production audit, enforcing CSP, axe, keyboard, focus, responsive, light, dark, reduced-motion, forced-colors, console, page-error, external-request, overflow, Petclinic, vanilla sample, Reference Application, and explicit-native rollback gates.
A failed closure retains its existing Causeway-owned native fallback and fails independently from other presentation families.
A deployment can roll back all adapters with the common native property without changing routes, GraphQL, persisted values, or application markup.
Qualified read-only presentation is limited to non-null standard text, multiline text, Boolean, enum or bounded choice, exact and machine numeric, local date, millisecond local time, and millisecond local date-time values.
Application renderers, protected values, nulls, references, resources, LOBs, offset, zoned, and legacy temporals, custom values, collections, and unsupported outputs retain their established renderers.
Only ordinary `<cw-action>` buttons are eligible for the action adapter; property edit, save, cancel, and clear controls, action prompts, menus, and shell controls remain outside it.
Grid qualifies separately only for connected active collections wider than 48rem with bounded windows, `CONFIGURED` ordering, supported Causeway semantic projections, and either a safe total or normalized paging metadata.
Grid never adds sorting, filtering, selection, editing, details, resizing, reordering, drag, row actions, GraphQL construction, routing, authorization, persistence pushdown, or application-facing Vaadin APIs.

== Canonical routes

The canonical object route is `<base-path>/object/<logical-type>/<identifier>`.
The public logical type and opaque identifier are independently UTF-8 percent-encoded as path segments without interpreting or normalizing identity.
Each source segment is bounded to 4,096 UTF-8 bytes and each final canonical encoded segment is bounded to 4,096 ASCII characters.
The encoded bound is normally decisive and permits long ASCII-oriented view-model mementos while bounding browser history, request, decoding, and rendering cost.
Browser generation and server parsing reject empty values, malformed Unicode or escapes, encoded separators, backslashes, controls, dot segments, overlong UTF-8 or encoded values, and non-canonical spellings.
Deployments with a proxy or container in front of the viewer must permit the documented canonical route size without decoding path separators.

An ordinary browser request receives a complete document containing one GraphQL client, stable menu bars, announcements, result presentation, and the requested route page.
A request carrying `HX-Request: true` receives only the route fragment and an `HX-Push-Url` response header.
A history-restore request receives only the route fragment and swaps it into the declared history element, so back and forward navigation never replace the stable shell or strand browser-bridge references.
The shell disables authorization-sensitive HTMX history snapshots and re-fetches the authorized route fragment on a history cache miss.
Normal home and result links remain canonical anchors, while the browser bridge enhances same-origin navigation with `htmx.ajax()` target, swap, push, and replace options.

== Generic and custom pages

Every object route creates exactly one `<cw-object-context>`.
Without an exact custom registration, its child is `<cw-object editable>` and the component uses its effective or fallback Causeway grid.

The preferred application customization is a UTF-8 HTML file beneath `META-INF/causeway/webcomponents/pages/`.
The filename before `.html` is the exact public logical type, so `petclinic.PetOwner.html` registers `petclinic.PetOwner` without an application bean, annotation, manifest, template controller, or client-side fetch.
The private resource is packaged in the application or a dependency jar but is not served by Spring's ordinary static-resource handler.
The viewer discovers all direct `*.html` children during startup, accepts at most 512 pages, accepts at most 256 KiB per page, and retains one immutable literal string for each accepted page.
Pages must be non-empty strict UTF-8, contain no NUL character, and use a filename-safe Causeway logical type.

A page contains only the markup placed beneath the viewer-owned route context.
It does not contain a document shell, GraphQL client, second object context, route interaction controller, or interpolated object identifier.
The viewer does not evaluate expressions, substitute route values, sanitize content, or expose the classpath resource as a public URL.
These files are trusted packaged application code and must never contain arbitrary user-supplied HTML without an application-controlled sanitization boundary.
Strict CSP remains active, so customization uses ordinary elements, classes, the configured same-origin application stylesheet, documented selectors, and `--causeway-*` variables rather than inline handlers or styles.

The compatible dynamic extension remains one Spring bean implementing `HtmxPageFragmentFactory` for a public logical type.
The factory receives only `HtmxObjectRoute`, not a metamodel object, persistence session, authorization object, or GraphQL response.
Two resources, two factories, or one of each claiming the same logical type fail during startup without using bean or classpath order.
A discovered resource that is unreadable, empty, oversized, malformed, invalidly named, or duplicated also fails startup rather than silently selecting the generic page.
Only complete absence of an exact registration selects `<cw-object editable>`.

Custom pages can compose ordinary HTML, application custom elements, `<cw-object>`, and semantic Causeway property, action, and collection elements.
Those elements consume the one nearest route context and therefore do not create a parallel data plane.
Removing an HTML file from the packaged application is the immediate rollback to retained grid-driven generic composition.

== Home and results

The shell extends targeted application-entry discovery only far enough to read the established optional object-home metadata and its public `_meta` identity.
A valid object home replaces the landing route with its canonical object route.
Absent, hidden, invalid, unsupported, or partially failing home state leaves an accessible landing page and stable menus.
The viewer does not invent a home service-action descriptor.

Default result policy routes object results, presents scalar and collection results in the shell result region, and announces void completion before authoritatively replacing the current route context while preserving the result announcement.
An application can provide `window.causewayHtmxPolicy.navigate`, `handleHome`, or `handleResult` functions and return `true` to claim the corresponding policy decision.
These policy functions receive semantic public payloads and do not replace component interaction behavior.

== Styling and accessibility

The shell loads `/causeway-webcomponents/theme.css` and `/causeway-htmx/causeway-htmx.css`.
The default theme follows the current Wicket viewer's application hierarchy with a sticky primary navigation surface, contained content, title and actions, cards, tabs, aligned properties, compact tables, bounded prompts, visible disabled state, and responsive collapse.
It uses ordinary CSS variables and documented light-DOM hooks rather than Bootstrap or Wicket markup.

The theme supports light, dark, reduced-motion, and forced-colors preferences.
At narrow widths navigation becomes disclosed, object columns and property labels stack, tables scroll inside their own collection regions, and the page does not overflow horizontally.
Applications may override the documented `--causeway-*` design tokens without replacing semantic behavior.

Navigation exposes loading and route announcements, moves focus to the installed route page, preserves existing content until replacement succeeds, and maps non-disclosing terminal state locally.
Escape, native controls, menu keyboard behavior, prompt focus containment, and visible focus remain component-owned.

== Petclinic reference application

Run the cohesive sample with:

[source,bash]
----
mvn -f viewers/webcomponents/pom.xml -Prun-sample-htmx-petclinic
----

Open `http://localhost:8080/htmx` for the generic viewer.
Open `http://localhost:8080/wicket/` and sign in as `sven` with password `pass` for the current Wicket comparison over the same model and fixture data.
See `../sample-htmx-petclinic/PROVENANCE.adoc` for the pinned Apache Petclinic source and porting boundaries.

== Non-goals

The module does not add routing awareness to `<cw-object>`.
It does not construct domain GraphQL operations, translate GraphQL values, parse effective grid or menu XML, expose metamodel internals, or define Vue and Svelte lifecycle APIs.
It does not require applications that use only the component library to adopt HTMX, Wicket, Petclinic, or the default theme.
The default toolkit policy adds no Grid query contract, upload adapter, unsupported temporal adapter, Flow, Binder, Pro component, server-side Vaadin state, telemetry, CDN asset, or application-facing raw Vaadin API.
