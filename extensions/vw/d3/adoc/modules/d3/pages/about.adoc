The D3.js module integrates with the xref:vw:ROOT:about.adoc[Wicket Viewer], rendering a domain property containing a JSON graph structure (nodes and links) as an interactive D3.js force-layout graph using the link:https://d3js.org/[D3.js] library.

Clicking a graph node invokes a configurable domain action whose single `String` parameter receives the clicked node's id.


== Setup

=== Dependency Management

In your application's top level `pom.xml`, add a dependency for this module's own bill of materials (BOM):

[source,xml,subs="attributes+"]
.pom.xml
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.apache.causeway.extensions</groupId>
            <artifactId>causeway-extensions-d3</artifactId>
            <scope>import</scope>
            <type>pom</type>
            <version>{page-causewayreleaseversion}</version>
        </dependency>
    </dependencies>
</dependencyManagement>
----

=== Dependencies / Imports

In those modules where there are domain objects with properties containing graph data (a JSON string with `nodes` and `links`), add a dependency/import to the applib module:

* add this dependency:
+
[source,xml,subs="attributes+"]
.pom.xml
----
<dependencies>
    <dependency>
        <groupId>org.apache.causeway.extensions</groupId>
        <artifactId>causeway-extensions-d3-applib</artifactId>
    </dependency>
</dependencies>
----

* and `@Import` this module:
+
[source,java]
.MyModule.java
----
@Configuration
@Import({
    CausewayModuleExtD3Applib.class,
    // ...
})
public class MyModule { ... }
----

In addition, in the webapp module of your application, add the following dependency:

[source,xml]
.pom.xml
----
<dependency>
    <groupId>org.apache.causeway.extensions</groupId>
    <artifactId>causeway-extensions-d3-wicket-ui</artifactId>
</dependency>
----

And in your application's xref:userguide::modules.adoc#appmanifest[App Manifest], import the extension's implementation module:

[source,java]
.AppManifest.java
----
@Configuration
@Import({
        CausewayModuleExtD3WicketUi.class,
        ...
})
public class AppManifest {
}
----


== Usage

To use the extension, annotate a `String` property (returning a JSON graph structure) with the xref:refguide:extensions:index/d3/applib/annotations/D3Graph.adoc[@D3Graph] annotation.

For example:

[source,java]
----
@D3Graph(clickAction = "selectNode")    // <.>
@Property()
@PropertyLayout(fieldSetId = "content", sequence = "1")
public String getGraph() {
    return "{\"nodes\":[{\"id\":\"A\",\"name\":\"Node A\"}],\"links\":[]}";
}

@Action
public GraphOwner selectNode(final String nodeId) {
    // handle node click
    return this;
}
----
<.> indicates that the property returns a JSON graph structure, and so should be rendered as an interactive D3.js force-layout graph.

The `clickAction` attribute specifies the id of a domain action (on the same object) that will be invoked when a graph node is clicked. The action must accept a single `String` parameter which receives the clicked node's id.

Optionally, you can also provide an implementation of the xref:refguide:extensions:index/d3/applib/spi/D3GraphAdvisor.adoc[] SPI, which advises on the graph dimensions, enable dragging/zoom, and the click action id. The framework provides sensible defaults (800x600, dragging and zoom enabled, no click action).


== Known Limitations

=== TYPE-level `@D3Graph` not supported

The `@D3Graph` annotation has `@Target({METHOD, FIELD, TYPE})`, meaning it was designed to allow annotating both individual properties/actions *and* whole domain classes. However, the metamodel processing factory (`D3GraphFacetFromAnnotationFactory`) is registered only for `FeatureType.PROPERTIES_AND_ACTIONS`. It never processes class-level annotations.

**Consequence:** Writing `@D3Graph` on a domain class like this has **zero effect**:

[source,java]
----
@D3Graph(clickAction = "selectNode")
public class GraphOwner { ... }
----

If TYPE support were added later, the UI module would also need a new `DOMAIN_OBJECT`-level `ComponentFactory` (alongside the existing `ATTRIBUTE_NAME_AND_VALUE` factory) to render an entire object page as a graph.

**Why it exists:** The current design follows the PDF.js extension pattern, where the viewer renders a *single property*. Supporting TYPE-level would be a more ambitious feature (whole-page graph rendering) that was not in scope for the initial implementation.

This limitation may be addressed in a future release.

=== Advisor `graphData` not merged

The `D3GraphAdvisor` SPI allows users to provide dynamic configuration for graph dimensions (`initialWidth`/`initialHeight`), interaction flags (`enableDragging`/`enableZoom`), and the click action (`clickAction`). The `D3GraphFacet.configFor(Class<?>)` method properly merges all of these advisor values into the `D3Config`.

However, `graphData` — the actual JSON payload describing nodes and links — is **excluded from this merge**. The graph data is always taken directly from the annotated property's runtime value, not from the advisor:

[source,java]
----
// In D3Panel.buildConfig():
var pojo = attributeModel.getObject().getPojo();
if (pojo instanceof CharSequence cs && !cs.toString().isBlank()) {
    config = config.withGraphData(cs);  // always from the property value
}
----

**Consequence:** An advisor cannot supply or override graph data. If a property returns `null` or an empty string, the graph renders with empty data — there is no way for an advisor to provide a fallback or computed graph.

**Why it exists:** This is an intentional simplification — the advisor `D3Config` advice interface may not have been designed to carry `graphData`, or the merge logic in `configFor(...)` was never extended to handle it. The `graphData` field on `D3Config` is settable via `withGraphData(...)`, so plumbing it through the advisor would be technically straightforward in a future update.
