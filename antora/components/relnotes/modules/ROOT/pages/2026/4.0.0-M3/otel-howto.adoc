This guide explains how Causeway supports open telemetry tracing and metrics, using first Boot-managed tracing and then using Agent-initiated tracing.
It uses the petclinic application to demonstrate.

It also outlines how to enable for your own applications.


== Start the local telemetry services

From the Causeway repository root, with Docker Desktop or a Docker daemon running and Docker Compose v2 or later available:

[source,bash]
----
./scripts/jaeger-local.sh start
./scripts/metrics-local.sh start
----

The first command starts Jaeger; the second starts Prometheus and Grafana and provisions Grafana's Prometheus data source.
Each script checks readiness independently.
The Petclinic launcher does not start or stop these services.
Repeated starts reuse running services.
All published ports bind to localhost.

[cols="1,2",options="header"]
|===
|Address |Purpose
|http://localhost:16686 |Jaeger trace UI
|http://localhost:4318/v1/traces |Jaeger OTLP HTTP trace receiver
|http://localhost:9090 |Prometheus query UI
|http://localhost:9090/api/v1/otlp/v1/metrics |Prometheus OTLP HTTP metrics receiver
|http://localhost:3000 |Grafana; initial login `admin` / `admin`
|===

Grafana queries the internal Docker address `http://prometheus:9090`; Petclinic sends to `localhost:9090` from the host.

Jaeger stores traces in memory, so
restarting Jaeger will lose earlier traces.
Similarly Prometheus and Grafana data directories use size-limited tmpfs; there are no persistent data volumes or host data directories.

To check status:

[source,bash]
----
./scripts/jaeger-local.sh status
./scripts/metrics-local.sh status
----

To inspect logs:

[source,bash]
----
./scripts/jaeger-local.sh logs
./scripts/metrics-local.sh logs
----


== Run with Boot-managed telemetry

Use a checkout whose Causeway dependencies have been built and installed into your local Maven repository.
The launcher builds the webcomponents modules; changes to other modules (such as the Wicket viewer) must be installed before running it.
The Petclinic launcher requires Maven and a supported build JDK, respects `JAVA_HOME` and `MVN`, and runs in the foreground:

[source,bash]
----
./viewers/webcomponents/sample-htmx-petclinic/run-with-telemetry.sh
----

[TIP]
====
Additional Maven options can be specified after `--`, for example `run-with-telemetry.sh -- -o` for an offline build.
====

The launcher activates the Maven `observation` profile for dependencies and the Spring `observation` profile for framework instrumentation and export configuration.

Boot owns the tracing, no Java agent is attached in this mode.
Micrometer meanwhile exports metrics.
The petclinic sample is configured so that traces are fully sampled and metrics are exported every ten seconds (this can be adjusted, see xref:#configuring-your-own-app[below].)

[[inspect-traces-and-metrics]]
=== Inspect traces and metrics

In Jaeger:

* select service *Causeway Pet Clinic*
* click *Find Traces*
* open a recent trace from a domain operation.
+
HTMX domain operations use `/graphql`; Wicket requests use `/wicket/` paths.

* Expand the span tree and inspect the spans
+
Span display names describe domain work, for example `act petclinic.PetOwner#updateName` or `Persist <entity type>`.
Mixed-in actions use the contributed action name rather than the mixin implementation's `act` method.
Mixed-in properties and collections use `prop <logical-type>#<member>` and `coll <logical-type>#<member>`; opening an owner can show `coll petclinic.PetOwner#visits`.
Regular property updates retain their `Property Update` spans.
+
Select a member span to inspect its full identifier: `causeway.action.id`, `causeway.property.id` or `causeway.collection.id`.
Action identifiers include declared parameter types, for example `petclinic.PetOwner#updateName(java.lang.String)`.
In Jaeger's *Attributes* search field, use `causeway.action.id="petclinic.PetOwner#updateName(java.lang.String)"` or `causeway.collection.id="petclinic.PetOwner#visits"` with *All Span Names* selected.
+
Display names retain identifier casing and are limited to 50 characters: long names lose their namespace first, then are truncated if still too long.
The full identifier attribute remains intact, so use it to distinguish compact names that look the same.
These names and attributes work in both Boot-managed and agent-managed tracing; they require no extra configuration.
+
NOTE: instance identifiers, object titles or argument values are _not_ included in the spans.

* on the top-level "entry" span, inspect its *attributes*:

** `causeway.execution.mode`
+
Records if the interaction was performed in the foreground (as the result of a user request) or in the background (from the command log extension's xref:refguide:extensions:index/commandlog/applib/job/RunBackgroundCommandsJob.adoc[] ).

* on any *Causeway Root Interaction* span, and inspect its *attributes*, such as:

** `causeway.interaction.id`
+
The UUID used by Causeway's interaction/command, in both tracing modes.
Note that this is distinct from Jaeger's trace ID and span ID.

** `causeway.interaction.language`
** `causeway.interaction.timezone`
** `causeway.user.name`
+
The authenticated username

** `causeway.user.impersonating`
** `causeway.user.multiTenancyToken`
+
\... if the user has a nonempty tenancy token (nb: the sample bypass user normally has none)

+
These attributes are _not_ added to the enclosing HTTP server span.

Note that static asset requests, such as `pdf.worker.min.mjs`, may contain only HTTP/security spans and therefore have no interaction UUID.


=== Micrometer

Underlying Micrometer operation names are categories such as `causeway.member.action` and `causeway.jpa.persist`.

Repeat operations on different owners:

* the Causeway member/JPA span names and member/entity metadata describe the operation and type

In Prometheus:

* open directly

In Grafana:

* log in (`admin` / `admin`).
* choose *Explore*
* select *Prometheus* in the data-source dropdown at the top, and switch to *Code* mode for PromQL.
+
The provisioned *Prometheus* source is also listed under *Connections → Data sources*.

After exercising Petclinic, wait 10–20 seconds and try these queries separately:

* JVM memory used bytes
+
[source,promql]
----
jvm_memory_used_bytes
----

* discover available Causeway metric names and counts their series:
+
[source,promql]
----
count by (__name__) ({__name__=~"causeway_.*"})
----

* select an actual metric name to inspect values.

Note that Prometheus metric names can differ from contextual span names, including dots translated to underscores.




== Switch to agent-managed tracing

The principal benefit of using agent-managed tracing is that the agent will instrument libraries, such as JDBC access.
This setup requires both:

* The JVM option `-javaagent:/path/to/opentelemetry-javaagent.jar`, which attaches the agent to supply the tracing SDK, exporter and automatic HTTP/JDBC instrumentation.
* The Spring profiles `observation,agent`: `observation` enables Causeway instrumentation, while `agent` selects Causeway's bridge to the agent and disables competing Boot tracing auto-configuration.

Activating the profiles does not attach the Java agent, and attaching the agent does not activate the profiles.
The sample launcher handles both settings for you when passed `--agent`.

=== Try it out

Stop the Boot-managed Petclinic process, keep all three telemetry services running, then add `--agent`:

[source,bash]
----
./viewers/webcomponents/sample-htmx-petclinic/run-with-telemetry.sh --agent
----

On first use, Maven downloads the (compatible) agent into the sample's `target/agents/` directory.
The launcher attaches it to the application JVM with `spring-boot.run.agents` (the Maven equivalent of `-javaagent`) and activates `observation,agent` with `spring-boot.run.profiles`.

Alternatively, the location of the agent JAR can be specified using an env var:

[source,bash]
----
OTEL_JAVAAGENT_PATH=/absolute/path/to/opentelemetry-javaagent.jar \
  ./viewers/webcomponents/sample-htmx-petclinic/run-with-telemetry.sh --agent
----


Micrometer continues to export metrics to Prometheus in both modes; the agent's own metrics exporter is disabled to avoid duplicate JVM metrics.
This setup also disables agent log export.

The launcher sets OTLP HTTP trace export, full trace sampling and service name *Causeway Pet Clinic* by default.


== Stop the local services

When finished, stop Petclinic with Ctrl-C, then stop all telemetry services:

[source,bash]
----
./scripts/jaeger-local.sh stop
./scripts/metrics-local.sh stop
----

The Jaeger command discards stored traces.
The metrics command discards metrics and Grafana UI changes and removes its Compose network.
Each script manages only its own services.
`./scripts/metrics-local.sh config` validates Compose configuration without starting services.


[#configuring-your-own-app]
== Configuring your own app.

Use the BOM-managed starter, which includes the Micrometer OTLP metrics registry:

[source,xml]
.pom.xml
----
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-opentelemetry</artifactId>
</dependency>
----

Activate `observation` alongside the application's other Spring profiles:

[source,yaml]
.application.yaml
----
spring:
  application:
    name: my-causeway-app
  profiles:
    active: observation
management:
  tracing:
    sampling:
      probability: 1.0
  opentelemetry:
    tracing:
      export:
        otlp:
          endpoint: http://localhost:4318/v1/traces
  otlp:
    metrics:
      export:
        enabled: true
        url: http://localhost:9090/api/v1/otlp/v1/metrics
        step: 10s
        aggregation-temporality: cumulative
----

Traces are sent to Jaeger, and metrics to Prometheus using the endpoints above.
The configuration records every trace (sampling probability) and exports metrics every ten seconds.


=== To configure agent-managed tracing

Keep the starter and Micrometer metrics configuration above, and add the BOM-managed OpenTelemetry bridge dependency:

[source,xml]
.pom.xml
----
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-otel</artifactId>
</dependency>
----

With `observation,agent` active, Causeway automatically connects its observations to the agent and disables competing Boot tracing configuration.
No custom Java configuration or manual Boot exclusions are needed.
The agent supplies trace sampling and export, so the Boot tracing settings above are unused in this mode; the Micrometer metrics settings still apply.

Obtain an OpenTelemetry Java agent JAR (the sample uses version 2.31.1), configure its export settings, and launch with both `-javaagent` and the `observation,agent` profiles:

[source,bash]
----
export OTEL_SERVICE_NAME=my-causeway-app
export OTEL_TRACES_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:4318/v1/traces
export OTEL_TRACES_SAMPLER=always_on
export OTEL_METRICS_EXPORTER=none
export OTEL_LOGS_EXPORTER=none
java -javaagent:/absolute/path/to/opentelemetry-javaagent.jar \
  -jar application.jar --spring.profiles.active=observation,agent
----

These settings send traces to Jaeger and leave metrics with Micrometer.
Causeway prevents the agent's `OTEL_METRICS_EXPORTER=none` setting from disabling Micrometer's metrics exporter.
JVM and Causeway metrics remain available; Boot's HTTP request observation meters are absent because the agent supplies HTTP instrumentation.

If you already provide a custom tracer or observation registry, Causeway uses it.
A custom registry must configure its tracing handlers to use the same single or primary tracer as Causeway.



== Current action context (CAUSEWAY-4058)

Applications can inspect the currently executing framework action through `InteractionProvider.currentActionInvocation()` and match its receiver, invoked identifier and rule-checking status with `isCurrentActionInvocation(...)`.
Mixin invocations also expose their domain-facing action identifier separately from the implementation method identifier.
This context API works with observations disabled and adds no spans; it provides the invocation information needed for the later application-defined spans capability.
See xref:refguide:applib:index/services/iactn/InteractionProvider.adoc[InteractionProvider] for examples and direct Java-call limitations.
